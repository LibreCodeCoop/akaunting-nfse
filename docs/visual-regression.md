# Browser visual regression baselines

The Full UI tier captures only two stable, critical NFS-e components:

- the Settings readiness summary;
- the NFS-e emission modal.

It deliberately does not snapshot whole pages.

Each PNG is generated by Playwright in the deterministic CI harness. The repository stores only the approved SHA-256 in `e2e/visual-baselines.json`. On a missing or changed baseline the test:

1. writes the actual PNG under `test-results/visual/`;
2. prints `VISUAL_BASELINE <key> <sha256>`;
3. fails the Full UI job;
4. leaves the PNG in the uploaded Playwright failure artifact.

To update a baseline, review the PNG artifact first. If the visual change is intentional, copy the printed SHA-256 into `e2e/visual-baselines.json` in a dedicated reviewed commit. Do not update a hash only to make CI green.

This keeps binary snapshots out of the repository while preserving a deterministic screenshot-level regression check and a reviewable artifact for every mismatch.
